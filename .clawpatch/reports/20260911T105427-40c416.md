## high: Configured arguments are interpolated into shell code without quoting

id: fnd_sig-feat-cli-command-f2682fcc7e-_5b52309309
category: security
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/slop_code/agent_runner/agents/cursor_cli (feat_cli-command_f2682fcc7e)

evidence:
- src/slop_code/agent_runner/agents/cursor_cli/agent.py:306-319 (CursorCliAgent._run_invocation)
- src/slop_code/agent_runner/agents/cursor_cli/agent.py:400-416 (CursorCliAgent._build_command)

The command is executed as shell text, but only the prompt is quoted. The configured binary, model, and extra_args are joined verbatim. Arguments containing spaces lose their boundaries, and shell metacharacters or command substitutions execute as code in the agent runtime. Exploitability depends on who controls configuration; ordinary arguments containing whitespace already cause incorrect execution.

recommendation:
Build a literal argv list and apply shlex.join to the entire invocation. Keep the fixed PATH export separate from the quoted invocation, or pass PATH through the runtime environment.

test analysis:
No tests were supplied or linked for this feature, so argument-boundary and shell-literal coverage cannot be verified.

suggested regression test:
Test that binary paths, model values, and extra arguments containing whitespace, quotes, dollar signs, and shell metacharacters reach a test executable unchanged and cause no shell side effects.

minimum fix scope:
CursorCliAgent._build_command and _run_invocation command serialization.

repro:
Configure an extra argument containing a literal command substitution, such as --example=$(printf injected). The generated shell command evaluates the substitution instead of passing the configured argument literally.

## medium: Trajectory detection crashes on valid JSON values that are not objects

id: fnd_sig-feat-cli-command-f2682fcc7e-_94fbda7f70
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Python source src/slop_code/agent_runner/agents/cursor_cli (feat_cli-command_f2682fcc7e)

evidence:
- src/slop_code/agent_runner/agents/cursor_cli/parser.py:35-48 (CursorCliParser.can_parse)
- src/slop_code/agent_runner/agents/cursor_cli/parser.py:65-70 (CursorCliParser.parse)
- src/slop_code/agent_runner/agents/cursor_cli/parser.py:87-89 (CursorCliParser.parse)

json.loads can return lists, strings, numbers, or None. Both detection and parsing immediately call .get without validating the result. Thus a JSONL file containing null or [] raises AttributeError during format detection instead of returning False or continuing to a valid initialization event. Parsing has the same issue, including assistant events whose message is null, and leaks AttributeError instead of a contextual ParseError.

recommendation:
Validate decoded event and nested message types before accessing fields. During detection, skip incompatible records; during parsing, report invalid event shapes with line-numbered ParseError exceptions.

test analysis:
No tests were supplied or linked. The excerpts show handling for invalid JSON syntax but no corresponding validation for valid JSON with incompatible shapes.

suggested regression test:
Cover scalar, null, and array records, plus invalid nested assistant message shapes. Assert detection remains boolean and parsing either accepts supported shapes or raises a line-numbered ParseError.

minimum fix scope:
CursorCliParser.can_parse and parse event-shape validation.

repro:
Pass a JSONL file containing null to can_parse or parse. Both raise AttributeError. An assistant event with message set to null also crashes parse.

## medium: Wire parsing depends on JSON member order and absorbs trailing diagnostics

id: fnd_sig-feat-cli-command-07e2c9afa6-_34fde2045e
category: api-contract
confidence: high
triage: contract-mismatch
status: open
feature: Python source src/slop_code/agent_runner/agents/kimi_cli (feat_cli-command_07e2c9afa6)

evidence:
- src/slop_code/agent_runner/agents/kimi_cli/parser.py:60-76 (_iter_jsonrpc_messages)
- src/slop_code/agent_runner/agents/kimi_cli/agent.py:433-446 (KimiCliAgent._parse_streamed_wire_event)
- src/slop_code/agent_runner/agents/kimi_cli/agent.py:369-375 (KimiCliAgent.run)

Both parsers recognize messages only when the first serialized member is exactly "jsonrpc". Valid JSON-RPC messages with reordered members or whitespace after the opening brace are silently discarded. The batch parser also appends every subsequent nonmatching line to the preceding message, so a diagnostic after a complete response makes that response fail JSON decoding. These framing assumptions can lose trajectory events and token usage, and cause a successful invocation to raise "completed without a final response".

recommendation:
Use shared JSON-aware framing for batch and streaming parsing. Validate jsonrpc after decoding, accept arbitrary member order and legal whitespace, and stop accumulating a message once its JSON object is complete while retaining support for multiline payloads.

test analysis:
No tests were included, so existing coverage could not be assessed. The supplied implementation contains no alternative framing path for these inputs.

suggested regression test:
Exercise equivalent wire messages across member order, legal whitespace, multiline control-character payloads, and surrounding diagnostic lines; assert identical events, usage, and final-result detection.

minimum fix scope:
Replace the framing logic in parser.py and reuse it for streamed event parsing in agent.py.

repro:
Pass '{"id":1,"jsonrpc":"2.0","result":{}}' to has_final_result: it returns false. Likewise, '{"jsonrpc":"2.0","id":1,"result":{}}\nDiagnostic message' returns false because the diagnostic is appended to the JSON.
